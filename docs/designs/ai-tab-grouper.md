# Design: AI Tab Grouper

## Problem Statement

Too many open tabs. Chrome's tab groups help, but making and maintaining them by hand is work nobody does. The extension reads tab titles and URLs, asks an AI which tabs belong together, and creates the Chrome tab groups itself.

## What Makes This Cool

Open a tab, and a few seconds later it slides into the right named group without you touching anything.

## Constraints

- Small. No build step, no npm dependencies, plain Manifest V3.
- Should be releasable to the Chrome Web Store later.
- Tab titles are often Chinese. The AI must handle Chinese.

## Premises

1. Tab titles plus URLs are enough to group well. No page content is read.
2. Tabs the user already grouped are never moved. Only ungrouped tabs get placed, so manual fixes stick.
3. A group needs at least 2 tabs. Singletons stay ungrouped.

## Approaches Considered

### A: Chrome built-in AI (Gemini Nano, Prompt API)
Free, private, no key. Rejected as the default: the Prompt API supports only English, Japanese, Spanish, German and French (no Chinese), needs 22 GB free disk plus more than 4 GB VRAM or 16 GB RAM, and is desktop only. A public release would silently fail for a large share of users.

### B: Claude API, user brings their own key (BYOK)
The extension calls `api.anthropic.com` directly with a key the user pastes into the options page. No server. This is what most AI tab groupers in the Web Store do.

### C: Claude API behind a hosted proxy
Users install and it works, no key. The developer pays for every call and has to run a server with rate limits and abuse protection.

## Recommended Approach

B for v1, with the API call isolated in one function so C can be added later without touching the rest.

Decided with the owner on 2026-11-16: the user supplies the key, and can switch freely between providers. Two wire formats cover them all: Anthropic's Messages API, and the OpenAI-style chat completions API (OpenAI, Gemini, OpenRouter, and any custom endpoint such as a local Ollama). Each provider remembers its own key and model.

Default model: `claude-haiku-5-5`. Grouping 50 tabs is about 2,500 input tokens and 500 output tokens, roughly $0.0005 per regroup at $0.10 / $0.50 per million tokens. Sonnet 5.5 costs 20x more and the task (sorting short titles into buckets) does not need it.

### Behavior

- Auto: when a tab finishes loading, wait 3 seconds for things to settle, then send that window's ungrouped tabs plus the existing group names. The AI assigns each tab to an existing group, a new group, or leaves it alone.
- Manual: clicking the toolbar icon regroups every tab in the current window from scratch.
- Skipped: pinned tabs, `chrome://` pages, tabs already in a group (auto mode only).
- An on/off switch for auto mode lives in the options page.

### Files

- `manifest.json`: permissions `tabs`, `tabGroups`, `storage`; host permissions for the four built-in providers; any other host is requested at save time for a custom endpoint.
- `background.js`: tab events, debounce, applies the plan with `chrome.tabs.group`.
- `grouping.js`: pure functions. Builds the prompt, validates the AI's answer. Unit tested.
- `ai.js`: the provider table and the one function that calls a provider.
- `options.html` + `options.js`: provider, API key, model, auto on/off.

### Privacy

The key is kept in `chrome.storage.local` (never synced). Tab titles and URLs go only to Anthropic, only for grouping. The options page says so in plain words, which the Web Store's Limited Use policy requires to be in the product itself.

- Load unpacked, paste a key, open 10 mixed tabs: they end up in sensibly named groups within about 5 seconds.
- Manually moving a tab to another group is not undone.
- `node --test` passes for the grouping logic.
